# v0.9 途中保存・復元

端末内のIndexedDB `drawindow-session` に1セッションを保存する。画像・座標・名前をサーバーへ送らない。ブラウザーの同一オリジンに属する保存のため、別URL・別端末へは引き継がない。複数タブの同時プレイでは最後の保存が残る。複数スロット・タブ間ロックは今回の範囲外。

- schema version 1。従来は言語・昼夜のみlocalStorageに保存しており、移行対象の途中セッション形式はなかった。その設定は引き続き使用する。将来の不明なversion、壊れた構造、無効な座標、消えたカタログIDは安全に拒否し、新しく開始できる。未知版を推測して変換しない。
- 現ラウンド、描画、10枚の記録、認識結果、元の日本語表記・意味、命名下書き、選択順序、UNDO/REDO/CLEAR履歴を保存する。カタログ全体の線画を毎回コピーせずIDで参照する。新しい辞書で派生する意味記録を再構築するときも「花／鼻」の原表記を使う。
- 最大500msごとの非同期チェックポイント。ポインターイベントごとのJSON変換はしない。非表示化/pagehide時は未保存の状態をflushする。OSによる強制終了直前の最後の500msや未完了トランザクションは失われる可能性があり、完全なクラッシュ耐久性を約束しない。
- タイトルで本人が「続きから遊ぶ」を選ぶまで再開しない。新しく開始すると保存を置き換える。途中でホームへ戻ると従来の退出確認が出て、承認すれば保存も消す。
- 認識中だった場合は絵を保ち認識エラー画面で待機し、再試行／描き直しを本人が選ぶ。古い応答・演出を無効化する新しいsessionIdを割り当てる。既に失敗済みのエラー理由と試行上限は保持する。課金や送信を伴うAPIセッションをオフライン版で再開しない。ビルドからもAPI認識器を除外する。
- しずくの描画／ためらい／描き直し途中は、保存した実際の選択を使って完成した絵を静かに表示する。新しい絵の選択や認識の再実行はしない。答え合わせ結果の再開は絵日記の先頭から表示する。
- 保存失敗、容量不足、IndexedDBが使用できない場合は絵をメモリー上に保持して表示する。保存できたようには扱わない。サイトデータ削除・ブラウザーの退避はキャッシュと途中保存のどちらも消しうる。

検証: `npx vitest run src/lib/sessionStorage.test.ts src/lib/useSessionPersistence.test.tsx --maxWorkers=2`。実Chromiumは `npm run package:offline` 後に `node scripts/qa-session-resume.mjs`。後者は実IndexedDBとディスクプロファイルを使用し、ブラウザープロセスを正常終了→新しいプロセスを同じプロファイルで通信遮断して起動する。保存・復元、CLEAR→UNDO/REDO、命名下書き、合成の認識中断チェックポイント、未知schemaを確認する。これはAndroid実機、OS強制終了、個人の手描き品質の証明ではない。
