# DRAWINDOW v0.10 文脈認識の設計

## 目的と境界

直前のしずくの正式名から次の語頭を予測するが、それはしずくの仮説である。プレイヤーが同じ名を思った保証はない。今回の成果はA/B/Cを同じ入力で比較する研究環境。本編の認識・採用291枚・進行・スコア・保存・演出は変更しない。既存PRを変更せず#29のHEAD 6194dcbd364bc7d041ce08de52deac8976c67b78を起点とする。

## 検討した実装方法

1. モデルを方式ごとに３回呼ぶ: 入力や初期化時間の差が比較を歪め、無駄な推論が増えるため採用しない。
2. １回の345クラス出力を固定し、純粋な解釈関数だけ変える: 今回採用。描画・語頭・順位が同じ状態で補正の影響を追える。
3. 文脈つきモデルへの再学習: 独立した人間データと費用・学習設計が必要。今回行わない。

ユーザーが指定した１回の推論と独立UIの方針に従い、追加の外部サービスや依存は導入しない。

## A/B/C

Aはv0.9の生Top-1、既存日本語対応表、未較正スコアfloor .05、unknownを再現する。現行の結果変換だけを共有の純関数へ抽出し、凍結した旧挙動との比較テストで同一性を確かめる。

Bは強い文脈優先。モデル上位候補の中で予想語頭に一致する最上位を優先する。既定探索範囲はTop-10、floor .05。語を生成しない。Aがunknownなら全方式unknownを保持する。範囲を明示して弱い画像根拠による悪化も記録する。

Cは画像主体。既定Top-3、最大スコア差 .08以内でのみ文脈候補を検討する。設定可能な安全上限はTop-5、差・強さ .08。強さ0は同点でもAを保持する。順位・差のguard方式と、guard内の候補に小さな加算を行うbonus方式を比較し、強さを設定可能にする。設定は研究上の仮定で、人間データから較正した値ではない。加算後の値も確率とは呼ばない。Aがunknown、語頭不明、「ん」での再開では補正しない。

全方式の候補名は既存345ラベルと177日本語対応に限る。読み・濁半濁音・小書き・長音は既存words.tsを使う。同音異義語を意味の正解と混同しない。次の絵が存在するかは採用候補の選択には使わず、後から別計測する。

## 情報の分離と記録

Runtime入力: 同じモデル候補345件、言語、直前のしずくの正式名（およびモデル失敗情報）。解釈関数に意図・人間が読んだ前絵の名前・正解クラス・感想を渡さない。

評価入力: 人間が結果取得後に記入する意図、前絵の読み取り、正解モデルクラス（対応外も可）、実際の継続・楽しさ・再遊意向・しずくらしさ等。正解クラスが不明なら意味精度を未評価にする。かな一致は別の読み一致であり、花／鼻の意味一致にしない。

各記録は生順位とスコア、モデル版、context仮説、A/B/C選択・元順位・変更理由・unknown・補正設定・処理時間を残す。推論は１回、設定変更では同じ候補を再利用する。各設定の結果を比較でき、改善/悪化/不変/未評価を別集計する。テンプレート存在・文字上の継続・観察した実プレイ継続を分ける。

## 開発画面と保存方針

`/?context-recognition` にマウス・指・ペンの本番WindowCanvasを使った独立画面を設ける。結果は描画・実行前に表示しない。新しい描画では前の結果を隠す。直前語・言語は推論時に固定して記録し、あとから変更した比較は同じ入力として数えない。認識と表情比較は独立した設定にする。

記録はメモリー内、本人の明示操作でのみJSON/CSVを書き出す。画像/ストロークの再利用データは別途明示的な同意・操作を必要とし、今回の既存v0.9のメタデータだけから復元しない。開発UI・解釈補正・評価・記録機能はimport.meta.env.DEVにより製品ビルドから除外する。通信はローカル配布資源の取得だけ、外部推論・画像送信なし。

## 評価と採否

合成fixturesは５ケース（助ける、前絵読み違い、しりとり間違い、未知/対応外、画像正解の破壊）と境界・異常入力の回帰を証明する。人間精度や楽しさには換算しない。旧ベンチマークは座標/画像を出力しないため、再推論に使えない記録は再利用しない。

人間では各人の同じ絵をA/B/Cで比較し、画像の正解を壊す割合、文脈が外れた群、未知群を別に見る。連鎖率だけでは採用しない。表情あり/なしの比較は認識方式を固定し、実際の５往復の体験・テンポ・すれ違い・しずくらしさを別に観察する。Cの本編採用は人間テスト後に別判断する。D候補は認識Aを固定し文脈は表情だけに使う案。
