## この段階で確認できたこと

20件の合成候補（うち正解モデル分類が確定した構成例10件）では、BはAに比べ２件を助け６件を壊し、既定Cは２件を助け４件を壊した。画像Aが正しかったケースを、文脈一致のために誤らせる現象を再現できた。文字上の接続はAの１件からBの14件へ増えるが、意味の正解と同じではない。これは狙って構成した例の内訳であり、方式の人間精度比較・優劣の推定には使えない。

Cは同一20入力でgap/bonus×強さ0/.02/.04/.08の８設定を比較した。強さ0はAを維持する対照条件。未知５件を全方式で保持し、モデル外３件は１件の棄却と２件の既知語誤断定を別に記録した。文脈だけで真のモデル外入力を見抜けるようになったわけではない。

- 基準テスト304件から全338件へ拡張し成功。A互換、１推論、正解情報を渡さない境界、異常候補、日英正規化、上下限、同音異義語、改善/悪化/OOVの区別、画面と書き出しを検証。
- 型検査・オフライン包装・配布スキャン成功。ビルドのmodule検査でsrc/devが製品コードに含まれていないことを確認。意図的に開発モジュールを含めたcanaryビルドが拒否される負例も成功。展開49項目のバイト一致も維持。
- 実モデルの合成円で345候補を取得し、同じ候補からCの２設定と独立した表情を比較、本人操作でJSON/CSVを書き出した。新しい描画では結果を隠す。390×844と1440×900で横溢れ・空白canvas・ページ実行エラーなし、外部要求0/POST0。これは人間の絵の認識証明ではない。

## 採否に必要な未検証事項

独立した人間の手描き精度、前絵を自然に読み違えた場合の悪化率、モデル外の物を描いた場合の過剰断定、端末ごとの処理時間・指操作、実際の５往復の自然さ・すれ違いの楽しさ・しずくらしさは未検証。比較画面で３方式を並べて見た感想は、本編でひとつを体験した証拠ではない。

Cの順位・差・bonusの上限は研究用の仮定であり、未較正スコアを正解確率にしたものではない。上限内でも文脈が誤りを増やせる。９リンク率は採否の単独目標にしない。クラス対応・unknownを都合よく書き換えない。

## 仮説と次の実験

1. 曖昧な画像で文脈が助ける群と、前絵読み違いで文脈が害になる群を、同じ人の中で分けて集める。
2. 先に決めた複数設定を同じ候補で比較し、改善と悪化を別々に出す。しずくの絵・合成スコアで調整した設定を、人間の独立検証済みと呼ばない。
3. 画像Aを維持し文脈は表情だけに使うD案と、弱いC案を分けて試す。Dなら画像だけで正しかった解釈を壊さず、しずくが続きを想像している感触を加えられる可能性がある。これは提案であり、楽しさの実測結果ではない。
4. Aが自然なら維持する。Cを採用する場合も、意図と認識・意味・文字上のつながりを分離したまま、別の承認・受入を行う。

研究画面はローカル開発サーバーから資源を読み込む必要がある。読み込み済みのモデルではHTTP遮断後の補正・書き出し・英語推論も確認した。研究画面の再読み込み／冷間起動を通信遮断で保証するものではない。製品版のPWAオフライン試験とは別の範囲である。
