## 3. 日本語・英語の語彙

| 指標 | 英語 | 日本語 |
| --- | ---: | ---: |
| モデルクラス数 | 345 | 345 |
| 対応クラス | 345 | 177 |
| 未対応クラス | 0 | 168 |
| 正規化した異なる認識語 | 345 | 174 |
| 本編選択プールのテンプレート | 309 | 332 |
| そのうち採用線画 | 291 | 291 |
| 異なる描画可能語 | 305 | 327 |
| 同じ名前の絵がない認識語 | 192 | 53 |
| 認識語に含まれない描画可能語 | 152 | 206 |
| モデルの有効出力から次の絵がないクラス | 0 | 0 |

英語の返信頭文字はa-zを網羅。日本語は「を」「ん」に返信開始語がない。「ん」は既存ルールどおり途切れて新しい絵へ再開する。英語x、日本語ぬ・め・るなどは候補が１語で反復しやすい。

1,024回（256 seed×日英×昼夜）の実選択関数による合成連鎖は全て完走。345英語＋177日本語の各有効モデル出力も本番reducerで検証し、uncovered_letterは0件。ガードの再現は、日本語のモデル外の「ゐ」、英語ではqの絵を明示的に除いたfixtureを使用した。これは本番語彙で自然発生した不具合として数えない。日本語未対応クラス、モデルが人の意図を当てる確率、モデル語彙にない語を人が描く可能性は別問題。

全語彙・語頭語尾分布・別名・同音異義語・正規化・seedと例: [集計](VOCABULARY_COVERAGE_v09.md) / [JSON](vocabulary-coverage-v09.json)。再実行: `npm run audit:vocabulary`。

## 5. 認識について確認したこと／未確認

学習notebookと公式bitmapの0背景・255線のサンプルを確認し、現行の背景0・線1前処理と整合する根拠を得た。ただし上流model cardの説明には逆極性の記述があり、パディング・太さ・変換が学習bitmapと厳密に同じとは未証明。前処理の閾値や正解への強制変換は行っていない。

Top-1を採用し、未対応や低スコアをunknown/失敗として保持する。順位スコアは未較正で、人の絵を当てる確率ではない。しずくのQuickDraw由来絵と学習データの重複を否定できない。過去の30/32は開発用の採用絵確認で、独立した人の手描き精度ではない。人の認識精度・しりとり継続率・楽しさの新しい数値はまだない。
