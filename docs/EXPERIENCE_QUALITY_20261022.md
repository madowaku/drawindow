## 理想の体験とMDE

理想は、操作の都合に意識を奪われず、相手の絵を想像し、自分の返事を描き、最後にふたりの解釈の違いを楽しめること。絵の上手さやスコアの高さを、理解し合えた証拠にしない。

今回のMDEは、**描き直しが怖くない → 自分の位置が分かる → 命名まで努力が守られる → 既存の十枚の絵日記に到達できる**こと。新しい報酬、語彙追加、絵の描き味の変更、ルール変更で品質向上を代用しなかった。

## 実現方法とOSS比較

| 方法 | 適性と判断 |
| --- | --- |
| 既存reducer内の描画だけに履歴を持つ | 採用。認識・会話・ラウンドの状態を巻き戻さず、点列・筆圧・時刻を保てる。履歴用に全点列を追加複製せず、immutableなスナップショットを共有 |
| [redux-undo](https://github.com/omnidan/redux-undo) | 汎用履歴の候補だが、本作はRedux未導入。公式リポジトリは2026-01-02にアーカイブ済み。依存追加・状態全体の履歴化より局所実装を選んだ |
| [perfect-freehand](https://github.com/steveruizok/perfect-freehand) | 入力点から筆圧付き輪郭を生成する方式。描き味改善の候補にはなるが、今回のデータ保護は解決せず、既存のガラス表現と認識画像の再評価が必要になるため見送り |

履歴の考え方は [Reduxの公式undo history解説](https://redux.js.org/usage/implementing-undo-history) と比較した。今回は新規依存を追加していない。OSSの状況は2026-10-22に一次資料で確認した。

## 残る課題と次の候補

1. **人間の短い試遊で本当の摩擦を測る。** 初回のルール理解、どの絵で迷うか、描く姿勢、答えあわせの気持ち、保存したくなるかを確認する。自動完走で代用しない。
2. **描き込み上限の無言の拒否を解消する。** 現在は256筆・16,000点を超える入力をcoreが拒否するが、Canvas側は採取を続ける。既存値を変えず、採取・受理・表示の状態を揃え、日英で穏やかな案内を出す。勝手な点列間引きはしない。
3. **中断からの復帰を検討する。** 今回はアプリ内ホーム操作を保護した。ページ再読み込み・タブを閉じる操作からの復元はない。セッション保存は保存期間・消去・共有端末での扱いも含めて設計してから採用する。
4. **作品の学びやすさを試遊から改善する。** 描いている間に相手の絵を見返せる小さな参照や、初回のルール提示は候補。ただし一枚の窓の演出と推測の遊びを変えるため、無断採用せず比較する。
5. **製品の正本と受入記録を整理する。** 古い直下・統合用・語彙追加・認識研究が分かれている。今回の改善をレビューしてから狭く統合し、研究機能や未採用の素材を一括で混ぜない。
