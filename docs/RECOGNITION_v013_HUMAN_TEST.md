# v0.13 人間テスト手順

## 1. 準備

固定モデルを `npm run prepare:local-ml` で準備してから `npm run dev -- --host 127.0.0.1`。認識APIやWorkerは不要。`/?recognition-benchmark` を開く。通信はモデル等の準備時だけ必要で、絵の認識・評価を外部送信しない。開発サーバー自体の再起動をネット切断状態で保証するテストではない。インストール済み販売相当ビルドのオフライン起動は別途検証する。

個人情報を記入しない。出力したJSON/CSVは本人がローカル保管し、共有するときは自分で内容を確認する。既定では絵・筆跡を含まない。再現実験が必要な絵だけ、比較前に明示チェックする。

## 2. 開発者の自由描画20〜30枚

1. 自由描画モードで、先に描く物を記録。出所を「いま人間が新しく描く」、用途を「改善・探索用」にする。描き手本人が操作し、合成入力・過去の見本のトレースを混ぜない。
2. 普通の物、未対応候補、曖昧な形を含め、日常の描き方で20〜30枚。自由描画の自動集計は意図する名詞がある絵に限る。意図がない線の負例は固定12問の第12題で測り、名詞一致の分母から除外する。
3. 同じ絵の6条件を比較。Top1の意図一致、納得できる別解、意味不明な誤認識、認識不能を人間が評価。Top3一致は別に入力。生スコアが高いから正解とはしない。
4. 初回と描き直しを混ぜない。描き直したら新しい描画として別記し、原画と修正の関係・回数を手元の匿名メモに残す。単純な同一筆跡の反復を独立した絵に数えない。
5. JSON/CSVを保存。原因別件数、言語別のunmapped/low_score/実行失敗、各条件の人間評価を比較する。資料・報告には実際の分子/分母・未評価件数と入力方法を記載。

## 3. 独立した2人以上×各12枚

固定12問を使用し、匿名ID P01/P02等を割り当てる。各人が新しい12枚を描き、納得度・短い理由・Top3一致を記録。12番目の意図なしscribbleは通常名詞一致11題から除外。手動再試行は初回集計から除外する。端末/入力方法/モデル版も残す。

このデータを改善に使った場合、最終評価には再利用しない。設定を選び終えたら、別の新しい絵を自由描画でholdout指定し、選んだ条件を事前に固定して評価する。同じ物を再び描いても別の新しい筆跡であることと、描き手・設定選択への関与を記す。少人数パイロットなので一般的な認識精度と断言しない。

## 4. 続け方 A / B の試遊

`/?recognition-recovery` のタイトルでAかBを選び、日本語/英語・DAY/NIGHTを組み合わせる。半数はA→B、残りはB→Aの順。各ゲームは新しい自分の絵で5往復。自然な認識失敗と意図不一致を記録する。認識できなかった時だけ、Aは線を直す、Bは本人が「わからないまま、次の一枚へ」を選ぶ。失敗を起こすための合成入力は人間試遊に混ぜない。

各セッションで完走/未完走、描き直し回数、救済回数をエクスポートする。未完走も捨てず、完走率の分母に含める。感想は結果画面で自然さ、負担、楽しさ、しずくらしさ、すれ違いの楽しさ、再遊意向を記入。未完走者には同じ質問を匿名の手元メモで聞く。絵日記で失敗絵が残り、救済先リンクが不明であることを本人に説明してもらう。

名前を後で入力しても救済先が「つながった」にならないこと、最後の絵は未認識であること、保存→再開→UNDO/REDO、音、PNG、またねを確認。実Androidで指の反応、表示、発熱・疲れ、推論/初回ロードを確認する。Cテンポ/D反応を好きかは認識の正誤と別に聞く。

## 5. Cの設計比較と採用判断

名前を先に入力するC案を紙の説明で提示し、「言葉を使わない会話」に合うか、AIが理解したと誤解しないかを聞く。実装したかのような完走数に含めない。

推薦はBだが、人間が自然と感じ、描き直し負担が下がり、すれ違いの面白さ・しずくらしさを損なわず、結果も理解できることを確かめてから本編採用を決める。前処理も同じく、探索と独立した最終評価で改善が見られるまでは現行維持。今回の人間認識率・完走率・好みは**未測定**。
